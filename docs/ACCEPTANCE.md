# 验证范围

## 自动化

0.4.0 在 Windows / Python 3.12 上通过 162 项回归，包括全局标题协议、超长文本标题续接、无效标题回退、大块递归拆分和结构配置缓存失效。源码通过 Ruff、发布隐私审计和 `git diff --check`；wheel 与 sdist 构建后再次通过制品审计，wheel 在隔离虚拟环境中安装并确认包版本为 0.4.0。

对一份 11958 字缓存样本进行纯本地请求规划，默认初始润色块为 5 个、标题批次为 1 个；同一文本按旧 600 字窗口为 20 个润色块和 2 个标题批次。该检查没有向模型发送正文，只验证请求数量与窗口行为；供应商响应耗时和大块一次通过率仍需在获准的数据上分别测量。

0.3.0 发布候选在 Windows / Python 3.12 上通过 152 项离线回归，随后增加非 UTF-8 管道场景，共 153 项。另用 100 分钟缓存视频验证 raw＋代表配图：2,552 条字幕的文本和 ID 全部保留，57 张图片，禁止 HTTP 请求下耗时 28.6 秒；恢复约 1.3 秒，输出哈希和修改时间不变。这不包含下载、ASR 或云润色耗时。

运行 `python -m pytest`。回归覆盖：

- 字幕 ID/时间校验、分组合并、数字与标点保护、递归缩块和原文回退。
- 全文语义标题、二级/三级层级、极长文本续接、无效模型输出回退。
- 模型失败、限流重试、敏感报错脱敏、缓存损坏和中断恢复。
- 稀疏/密集配图、OCR 可选性、并行一致性、全帧尺寸与图文引用。
- 二维码登录的等待扫码、等待确认、成功保存、超时/过期和临时图片清理（模拟 API，不使用真实账号）。
- raw/no-images 的网络禁止执行、workspace 隔离、只读计划与 JSON 接口。
- Skill 从不同目录启动、完整缓存恢复、打包后的默认配置。

CI 在 Windows/Linux 与 Python 3.10、3.12、3.13 上运行基础依赖测试、静态检查、依赖检查、离线诊断和安装包检查。最新状态以 [Actions](https://github.com/yvxinn/BiliDraft/actions) 为准。合成媒体测试使用 FFmpeg；真实账号和模型不进入 CI。

## 发布验收

1. 静态检查、测试、Skill frontmatter 与引用完整性验证。
2. 对有权使用的缓存视频运行代表配图和 raw 模式；断网恢复时验证输出哈希不变。
3. 从干净源码构建 wheel/sdist，在源码目录外验证安装、导入、CLI 与 Skill 入口。
4. 审查 Git 文件清单、历史和提交元数据；扫描包内凭据、个人路径、真实课程素材与残留实验内容。
5. 推送后核对远端提交与 CI，而不把本地通过等同于跨平台通过。

本仓库不包含真实课程、登录凭据或私有验收日志。公开测试数据均为合成内容。性能记录见 [PERFORMANCE.md](PERFORMANCE.md)。

## 已知限制

没有通用人工标注集，不宣称截图 precision/recall 指标。代表模式故意省略画面；原始字幕可能本身有 ASR 错误。长度保留率不代表信息保真，数字检查不能覆盖所有术语错误。即使退出码为 0，发布讲义前仍需人工复核和内容授权。

可选 ASR/OCR 的实际性能取决于模型、硬件和内容，基础 CI 不下载其权重。下载、平台登录与云端模型会受上游变化影响，模拟 API 的测试不保证账号持续有效。
